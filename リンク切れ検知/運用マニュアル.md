# 求人リンク切れの運用マニュアル

この仕組みを初めて触る人向けの手順です。2026-11-11 時点の実装とシートの状態を書いています。数値は、その日の記録です。

## 目的

ダイレクトスカウト（RDS）とリクルートエージェント（RAG）の企業特集に載っている求人リンクのうち、切れているものをスプレッドシートに集めます。掲載ページから切れた求人を全部外したとき、生きている求人が残るかどうかも付けます。

WordPress の求人カセットを外す処理、記事そのものの削除、代わりの求人を足す処理は、まだありません。月曜に動くジョブは、一覧の追記と「掲載求人有無」の更新までです。

## 今動いていること

- スプレッドシートに紐づいた Apps Script が、毎週月曜に公開HTMLを走査する。
- 新しく切れた求人だけを、RDS と RAG の一覧タブの末尾へ追記する。
- 同じ走査で、一覧タブの M列「掲載求人有無」を更新する。
- 手元の `check_rds_links.py` と `check_rag_links.py` で、同じ種類の確認を再実行できる。手元のスクリプトはシートを更新しない。

## まだ動いていないこと

- 切れている求人カセットを WordPress から外すこと。手順の文章には「自動」とあるが、月曜のジョブは削除しない。
- 記事ページの非公開・削除。求人の追加。
- O列「方針」、P列「追加求人URL」、Q列「PD対応」を自動で埋めること。人が書く列で、週次処理は上書きしない。
- 5xx を「切れ」から外すこと。あとの「判定」に、コードが今やっていることを書いた。

## 判定

週次の `judge_` と、手元の `judge` が使っている条件です。

掲載URLへの1回目のリクエストは、リダイレクトを自動では追いません。返ってきたステータスを見て、次のようにします。

| 掲載URLの結果 | 一覧への追記 |
| --- | --- |
| 400 以上 | 追記する。F列は「求人終了」。G列にそのステータス |
| リダイレクトで、遷移先も 400 以上 | 追記する。F列は「旧URL。遷移先の求人も終了」。H列に遷移先、I列に遷移先のステータス |
| 200 | 追記しない |
| リダイレクトで、遷移先が 400 未満 | 追記しない。遷移先がさらにリダイレクトしていても、その先は見ない |
| リダイレクトで、遷移先の取得に失敗した | 追記しない |
| 通信失敗でステータスが取れない | 追記しない |

リダイレクトとみなすコードは、手元の Python が 301 / 302 / 303 / 307 / 308 です。Apps Script は、300番台で Location があるものを1回だけ取りにいきます。どちらも、遷移先を見るのは1回だけです。

通信失敗（タイムアウトや名前解決の失敗で、ステータスが無い）は切れにしません。掲載求人有無でも、残っている側に数えます。

ステータスが 400 以上のときは切れにします。今の `judge` と `judge_` は、404 も 500 番台も、400 以上として「求人終了」にします。5xx を切れから外し、掲載求人有無でも残っている側に数える変更は、まだ入っていません。削除を将来付けるときの基準は、この一覧判定より狭くします。削除の節に書いてあります。

同じ切れを二重に足さない鍵は、掲載ページURLと求人URLです。クエリ（`?` 以降）と末尾のスラッシュを除いた組が同じなら、既存行です。週次はシートの C列と E列を見ます。手元スクリプトは `state/` の組を見ます。

## 掲載求人有無

列名は「掲載求人有無」です。そのページから、切れている求人を全部外したとしたら、生きている求人が残るかを書きます。

- 生きている求人が1件も残らないときが「なし」。
- 1件でも残るときが「あり」。
- 削除の成功・失敗では変えません。
- 求人URLの取得に失敗したものは、残っている側に数えます。「なし」にしません。
- 公開ページを HTTP 200 で読めて、求人カードが0件なら「なし」。
- 公開ページの取得に失敗したとき、週次はそのページの M列を書き換えません。「なし」にも「あり」にもしません。

生きている側に入るのは、判定が「追記しない」になった求人です。200、遷移先が 400 未満、遷移先の取得失敗、通信失敗がここに入ります。400 以上（今の実装では 5xx を含む）は、残っている側に数えません。

ページが後から読めなくなっても、シートの既存行は残します。週次は行を消しません。

2026-11-11 の公開ページ判定:

- RDS は、求人がある記事156件のうち、なし 74、あり 82。一覧上の切れ行は584、対象記事は124。
- RAG の一覧上は、なし 8ページ（21行）、あり 8ページ（23行）。
- RAG の記事 33211 は、ページ自体が 404 で「なし」。
- RAG の 34415、33767、36033 は HTTP 200 だが求人カードが0件で「なし」。求人を載せていないページの可能性があるので、PD が確認するときに見る。

## 毎週何が走るか

スプレッドシートに紐づいた Apps Script です。

- プロジェクト名: 求人リンク切れ週次チェック
- エディタ: https://script.google.com/home/projects/16d7rh9Hblo47vCrcwn5NwnPc9LkmGtb7A0zhU3yI0FJlwo0F4WVFvD6_/edit
- ソースの正: `apps-script/WeeklyLinkCheck.gs`
- 関数: `weeklyJobLinkCheck`
- 時刻: 毎週月曜日。日本時間 9:00〜10:00 のあいだのどこか。`atHour(9)` と `nearMinute(0)`、タイムゾーン `Asia/Tokyo`。Apps Script の週タイマーは、9:00 ちょうどには鳴りません。
- トリガーは既に1つあります。`installWeeklyTrigger` を再実行して二重にしないでください。この関数は、`weeklyJobLinkCheck` のトリガーが1つでもあれば「トリガーは既にあります」と出して増やさない実装です。それでも、運用では再実行しません。トリガー画面で本数が1つかを見ます。

記事一覧は1ページ100件です。Apps Script の `listJson_` は10ページ（最大1000件）まで取ります。Python は短いページが返るまで取ります。

`weeklyJobLinkCheck` がやること:

1. RDS の公開記事を、カテゴリ ID 185（企業特集）で一覧する。
2. RAG の公開記事を、投稿タイプ company で一覧する。
3. 各公開HTMLから求人リンクを読む。
4. 求人URLを判定し、シートに無い組だけを末尾へ追記する。新しい行の L列は「未対応」、N列は空。
5. 同じ走査の結果で、M列「掲載求人有無」を更新する。

やらないこと:

- WordPress の求人カセット削除
- 記事の非公開・削除
- 代替求人の追加
- 既存行の L列、O列、P列、Q列の上書き
- 既存行の削除日の上書き

月曜のジョブが見るのは公開ページです。スクリプトプロパティのパスワードは使いません。`checkWpLogin` と `probeRagRaw` は週次トリガーに紐づいていません。

## パスワードの入れ替え

週次の一覧更新にパスワードは要りません。WordPress へ書き込む処理を将来付けるときと、ログイン確認のために、Apps Script のスクリプトプロパティへ置きます。

プロパティ名は次の4つです。名前は変えないでください。

- `RDS_WP_USER`
- `RDS_WP_APP_PASSWORD`
- `RAG_WP_USER`
- `RAG_WP_APP_PASSWORD`

ユーザー名は、RDS も RAG も `aibot` です。アプリケーションパスワードは、各サイトの WordPress プロフィールで発行します。値を置く場所はスクリプトプロパティだけです。チャット、git、スプレッドシート、このマニュアルには書きません。チャットにパスワードが出たときは、そのパスワードを取り消して、プロフィールで再発行します。

コードは使う直前にスペースを除きます（`replace(/ /g, '')`）。プロパティにスペース付きで入っていても、リクエストでは除いた値を使います。

入れ替え手順:

1. 対象サイトの WordPress に `aibot` で入る。
2. プロフィールのアプリケーションパスワードで、新しいパスワードを発行する。RDS と RAG は別サイトなので、それぞれで発行する。
3. 漏れたパスワードや、使わなくなったパスワードは、同じ画面で取り消す。
4. Apps Script のプロジェクト設定にあるスクリプトプロパティを開く。キー名は上の4つのまま、パスワードの値だけを差し替える。
5. エディタで `checkWpLogin` を手動実行する。ログに `RDS users/me 200` と `RAG users/me 200` が出れば通っています。ログに出るのはプロパティの文字数と HTTP ステータスです。パスワードの値は出ません。
6. この関数を週次トリガーに追加しない。

## やってはいけないこと

- `installWeeklyTrigger` を再実行して、月曜のトリガーを二重にしない。
- 週次ジョブに、削除・投稿の更新・`checkWpLogin`・`probeRagRaw` を紐づけない。
- 記事ページ自体を削除しない。非公開にもしない。求人カセットを外す話と、記事を消す話は別です。
- 代替求人を自動で追加しない。追加する URL は、div が P列に書き、PD が確認します。
- 既存行の L列「対応」、O列「方針」、P列「追加求人URL」、Q列「PD対応」を、週次処理で上書きしない。
- `HEADER` に O〜Q を足して、追記範囲を人手の列まで広げない。
- FAQ、掲載リスト、進捗管理、フォーム回答など、指定の3タブ以外を更新しない。
- 手元の CSV で一覧タブを置換しない。
- アプリケーションパスワードを、チャット、git、シート、このマニュアルに書かない。
- `out/` の生成 CSV をコミットしない。
- レンダリング済みの HTML を、WordPress の本文へ書き戻さない。将来編集するのは `content.raw` です。
- 通信失敗や 5xx を理由に、求人カセットを削除しない。
- 削除の試験で、本番の記事を更新しない。先に対象一覧だけを出す。

- 通信失敗と 5xx は削除しない。一覧の `judge_` は 400 以上を切れにします。削除の条件はそれより狭く、確定した 404 に限定します。

編集の仕方:

- 認証付きで `context=edit` を付け、`content.raw` を読んで書き換える。
- レンダリング済み HTML を書き戻さない。
- 認証はスクリプトプロパティ。上の「パスワードの入れ替え」の4つの名前を使う。
- テストでは本番記事を更新しない。まず、書き込み無しの対象一覧だけを出す。

ブロック:

- RDS のブロックは `acf/beard-bear-block-job-links`。求人URLは `job-links_N_url`。1記事に複数あり、2つが中心。同じURLが複数ブロックに入る。外すときは、その記事の全ブロックから外す。
- RAG のブロックは `rag-blocks/recruit`。求人URLは `rag-blocks-recruit-items_N_rag-blocks-recruit-item-url`。同様に、ブロックが2つあることが多い。全ブロックから外す。
- 削除できたら、その行の L列を「削除対応済み」にし、N列に削除日を入れる。失敗したら L列を「削除失敗」。記事ページは削除しない。求人は追加しない。M列「掲載求人有無」は、削除の成否では変えない。

リポジトリにある読み取り専用の関数は `probeRagRaw` だけです。RAG の `content.raw` を読み、切れている求人がどの記事の何番目のブロックにあるかをログへ出します。書き込みはありません。週次トリガーには紐づけません。RDS の同等の関数は、このリポジトリにはありません。

2026-11-11 に、削除せずに作った対象一覧（`out/` にあり、git には入っていない）:

削除関数を書くときは、シートの行数ではなく、`content.raw` 上で見つかったブロック行を対象にします。同じURLが複数ブロックにあれば、そのすべてを外します。
